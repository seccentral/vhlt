# Developer Guide

## What This Project Is

VHLT is a set of command-line tools for compiling Half-Life maps (`.map`) into BSP files (`.bsp`):

- `hlcsg`: geometry construction and clipping.
- `hlbsp`: BSP tree, portals, and surfaces.
- `hlvis`: visibility (PVS) computation.
- `hlrad`: lighting and radiosity.
- `ripent`: entity and texture data editing in BSP files.

## Repository Layout

- `common/`: shared code used by all tools (math, BSP I/O, logging, threading, file helpers).
- `hlcsg/`, `hlbsp/`, `hlvis/`, `hlrad/`, `ripent/`: tool-specific sources and headers.
- `docs/`: user manual (`user/manual.md`), developer guide (`developer/developer.md`), and Doxygen template (`api/Doxyfile.in`, configured into the build directory by CMake).
- `audits/`: audit reports and handling status.
- `tools/regress.ps1`: deterministic map-compile regression check (see Tests).
- `CMakeLists.txt`, `CMakePresets.json`: build configuration (presets `windows` and `linux`, Ninja generator).
- `cmake/toolchains/`: Zig toolchain files (`zig-windows-x86_64.cmake`, `zig-linux-x86_64.cmake`, shared `zig-common.cmake`).
- `.clangd`: clangd configuration (uses `build/windows/compile_commands.json`). `.clang-tidy`: lint checks.

## Build

Requires CMake 3.16 or newer, Ninja, and Zig 0.17.1 on `PATH`. Zig's bundled Clang compiles both targets, so there is no other compiler to install.

```sh
cmake --preset windows && cmake --build --preset windows    # build/windows
cmake --preset linux   && cmake --build --preset linux      # build/linux (cross-compiled, glibc 2.28+)
cmake --build build/windows --target docs                   # build/windows/docs/html (needs Doxygen)
cmake --build build/windows --target package                # build/windows/vhlt-<version>-win64.zip
cmake -S . -B build/lint --preset windows -DVHLT_CLANG_TIDY=ON && cmake --build build/lint   # clang-tidy
```

Both presets build with `-Wall -Werror`; `-DVHLT_WERROR=OFF` disables `-Werror` for a one-off diagnostic build. The Zig toolchain sets `-Wno-date-time`, because Zig makes that warning an error and the version banners use `__DATE__`, and `-s`, which strips Release binaries. Windows binaries depend only on system DLLs (`kernel32`, `ucrtbase`). Zig's Windows target uses the open-source mingw-w64 headers internally, which is why `__MINGW32__` is defined and the `#ifdef __MINGW32__` guards in `common/` remain.

## Entry Points

- `hlcsg/qcsg.cpp` (`main`): CSG processing.
- `hlbsp/qbsp.cpp` (`main`): BSP processing.
- `hlvis/vis.cpp` (`main`): visibility.
- `hlrad/qrad.cpp` (`main`): lighting.
- `ripent/ripent.cpp` (`main`): entity editing.

## Key Shared Modules

- `common/cmdlib.h` / `cmdlib.cpp`: core macros, string helpers, path helpers.
- `common/bspfile.h` / `bspfile.cpp`: BSP structures and I/O.
- `common/mathlib.h` / `mathlib.cpp`: vector/matrix math.
- `common/threads.h` / `threads.cpp`: thread pool.
- `common/log.h` / `log.cpp`: logging.
- `common/winding.h` / `winding.cpp`: winding/geometry utilities.

## Global State

The codebase uses extensive global state (e.g., `g_entities`, `g_dmodels`, `g_numtexinfo`). New work should be aware that many functions operate on globals rather than passed-in contexts.

## Threading

`RunThreadsOn` / `RunThreadsOnIndividual` in `common/threads.cpp` drive parallel loops. Worker functions share global state; locking is via `ThreadLock()` / `ThreadUnlock()`. The thread count is clamped to `[1, MAX_THREADS]` (64) because per-thread arrays are fixed-size.

## Input Validation

Every reader of external data must validate counts, offsets and sizes before allocating or indexing. Reuse the shared checks instead of writing new ones:

- `CopyLump` (`common/bspfile.cpp`): per-lump bounds against the file size and destination capacity.
- `ValidateMiptexHeader` (`common/bspfile.h`): miptex dimensions, mip offsets and data size for BSP and WAD textures. Header-only miptex entries (`offsets[0] == 0`) reference an external WAD and carry no pixel data.
- `MAX_MAP_PORTALS` (`common/bspfile.h`): shared `.prt` portal limit for hlbsp and hlvis.

Use `safe_snprintf` / `safe_strncpy` / `safe_strncat`; the `strcpy_s` / `sprintf_s` compatibility macros have been removed.

Before fixing a code path, confirm it is compiled in: the feature macros in `common/cmdlib.h` compile out large regions (for example `hlcsg/autowad.cpp` and `hlcsg/wadinclude.cpp`).

## Tests

There are no unit tests. Verification is via build, docs, packaging, smoke runs, and the map-compile regression harness:

```sh
# Windows
powershell -ExecutionPolicy Bypass -File tools/regress.ps1 `
    -MapDir D:\vhlt-maps -LightsRad D:\vhlt-maps\lights.rad `
    -WadDir "D:\Half-Life\valve" -UpdateBaseline
powershell -ExecutionPolicy Bypass -File tools/regress.ps1 `
    -MapDir D:\vhlt-maps -LightsRad D:\vhlt-maps\lights.rad `
    -WadDir "D:\Half-Life\valve"

# Linux (same baseline format)
tools/regress.sh --map-dir /srv/vhlt-maps --lights-rad /srv/vhlt-maps/lights.rad \
    --wad-dir /srv/half-life/valve --update-baseline
tools/regress.sh --map-dir /srv/vhlt-maps --lights-rad /srv/vhlt-maps/lights.rad \
    --wad-dir /srv/half-life/valve
```

The harness runs `hlcsg`, `hlbsp`, `hlvis -full` and `hlrad -extra` on every `.map` in the map directory, with `-threads 1`, and hashes the `.bsp`, `.prt` and `ripent -export` entity text. It normalises the `compiler` date, so the hashes remain valid across days. `--wad-dir`/`-WadDir` rewrites the worldspawn `wad` key to the local WADs, so the same maps work on any host; only the WAD base names end up in the BSP. Reference maps and WADs are third-party assets and must stay outside the repository. Maps are compiled in parallel; each individual compile is single-threaded because threaded compiles are not byte-identical run to run. The `.prt` layout can differ between the Windows and Linux builds, so keep a separate baseline per platform.

Running a tool with no arguments prints its version banner and exits with code 1; smoke checks must accept that exit code.
