# Developer Guide

## What This Project Is

VHLT is a set of command-line tools for compiling Half-Life maps (`.map`) into BSP files (`.bsp`):

- `hlcsg`: geometry construction and clipping.
- `hlbsp`: BSP tree, portals, and surfaces.
- `hlvis`: visibility (PVS) computation.
- `hlrad`: lighting and radiosity.
- `ripent`: entity and texture data editing in BSP files.

## Repository Layout

- `common/`: shared code used by all tools (math, BSP I/O, logging, threading, file helpers).
- `template/`: template math and reference-counting headers.
- `hlcsg/`, `hlbsp/`, `hlvis/`, `hlrad/`, `ripent/`: tool-specific sources and headers.
- `docs/`: user manual (`user/manual.md`), developer guide (`developer/developer.md`), and Doxygen configuration (`api/Doxyfile`).
- `audits/`: audit reports and handling status.
- `CMakeLists.txt`, `CMakePresets.json`: build configuration.

## Build

```sh
cmake -S . -B build -G "MinGW Makefiles"   # Windows/MinGW
cmake --build build
cmake --build build --target docs
cmake --build build --target package
```

## Entry Points

- `hlcsg/qcsg.cpp` (`main`): CSG processing.
- `hlbsp/qbsp.cpp` (`main`): BSP processing.
- `hlvis/vis.cpp` (`main`): visibility.
- `hlrad/qrad.cpp` (`main`): lighting.
- `ripent/ripent.cpp` (`main`): entity editing.

## Key Shared Modules

- `common/cmdlib.h` / `cmdlib.cpp`: core macros, string helpers, path helpers.
- `common/bspfile.h` / `bspfile.cpp`: BSP structures and I/O.
- `common/mathlib.h` / `mathlib.cpp`: vector/matrix math.
- `common/threads.h` / `threads.cpp`: thread pool.
- `common/log.h` / `log.cpp`: logging.
- `common/winding.h` / `winding.cpp`: winding/geometry utilities.

## Global State

The codebase uses extensive global state (e.g., `g_entities`, `g_dmodels`, `g_numtexinfo`). New work should be aware that many functions operate on globals rather than passed-in contexts.

## Threading

`RunThreadsOn` / `RunThreadsOnIndividual` in `common/threads.cpp` drive parallel loops. Worker functions share global state; locking is via `ThreadLock()` / `ThreadUnlock()`.

## Documentation

- User manual: `docs/user/manual.md`.

## Tests

There are no automated tests. Verification is via build, docs, packaging, and smoke runs of each binary.
